GeckoRegen

GeckoRegen is the validation gate that makes Bright Data production-safe. BD’s Self-Healing API returns a new scraper — it does not verify that the new scraper actually works. We re-run and schema-check before accepting.

What is live vs fallback

Live Bright Data collectors: FCA (751 records), FINMA, BD Test Shop (https://ecommerce-shop-brd.vercel.app — public, BD can reach it).

Fallback (pre-recorded): ESMA, BaFin, MAS. These have active: 0 so Monitor never fires a stub collector. Rows are tagged snapshot_id = fallback:synthetic. MAS is BD-blocked.

Simulate Break swaps local sandbox/index.html (view at /sandbox) so you can see the redesign. The following BD scan hits the public Test Shop URL — not localhost. Cloud scrapers cannot fetch your machine.

How to Read the Health Grid

Each regulator is a glass node. The amber strip and status label tell you scraper health:

Healthy — fields populated
Degraded — partial failure
Broken — healing required

On break the node pulses error-red. On heal it pulses amber. Updates arrive live over SSE.

What Happens When a Scraper Breaks

  1. Detector diffs current output against the last-known-good JSONL snapshot
  2. Healer builds a contextual prompt and sends it to Bright Data’s Self-Healing API
  3. BD regenerates scraper code. GeckoRegen polls until the job is ready
  4. Validator re-runs the scraper: population ≥ 90%, format consistent, record count stable
  5. Pass → health turns healthy. Fail → sharper prompt, max 3 attempts
  6. Memory stores what broke, which prompt worked, and how long it took

Impact correlation (implemented)

Memory does not embed documents. It scores historical changes with SequenceMatcher on title (50%), category (30%), and summary (20%). Exposed as GET /api/similar?title=...&category=....

Worked example from this dataset: ESMA fallback row “Guidelines on crypto-asset service providers and data retention” (category: guidance) is the same family as FCA live items on crypto guidance and data-retention themes. The API returns the nearest titles with a similarity score and a note (same category, similar title).

That is the GDPR-style claim, scoped to what the code actually does: “this looks like a guidance/retention change you have already seen,” not a legal opinion engine.

Pre-recorded heal (FCA)

If credits or time block a live heal, the timeline can show a prior FCA run: field summary null → contextual prompt → validation population 94.11% on 751 records → accepted in 1 attempt, 47s. Marked in validation_details as pre-recorded prior BD heal run.

Architecture

  • bd_client.py — Bright Data API client
  • db.py — SQLite (regulators, health_scores, changes, healing_events, regulator_profiles)
  • detector.py — snapshot diff, failure detection, severity
  • healer.py — heal prompt, BD Self-Healing API, validation gate
  • memory.py — profiles, correlation, timeline
  • monitor.py — orchestrator
  • adapter.py — adaptive scan frequency
  • server.py — Flask + SSE
